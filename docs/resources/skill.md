# anthropic_skill (Resource)

Creates and manages a custom Skill on the Anthropic platform (beta). Skills are uploaded from local files and can be attached to Managed Agents.

> **API**: `POST/GET/DELETE /v1/skills[/{id}]` (Skills API).
> **Auth**: Standard API key (`api_key` / `ANTHROPIC_API_KEY`).
> **Beta header**: `anthropic-beta: skills-2025-10-02`.
> **Cost**: Free for management, billable when used.

## Example Usage

```hcl
resource "anthropic_skill" "example" {
  display_title = "Example Skill"
  # Explicit patterns avoid sweeping the Terraform config itself into the
  # bundle. The provider preserves each file's path relative to the bundle
  # root, so SKILL.md can reference files in subdirectories at runtime.
  files = [
    for f in setunion(
      fileset(path.module, "SKILL.md"),
      fileset(path.module, "references/**"),
    ) : "${path.module}/${f}"
  ]
  force_destroy = true
}

output "skill_id" {
  description = "ID of the skill."
  value       = anthropic_skill.example.id
}

output "skill_source" {
  description = "Source of the skill."
  value       = anthropic_skill.example.source
}
```

## Schema

### Required

- `files` (List of String) Local file paths to upload for the skill. Must include a `SKILL.md` file at the root of the directory.

### Optional

- `display_title` (String) Human-readable display title for the skill. Not included in the prompt sent to the model.
- `force_destroy` (Boolean) When `true`, all skill versions are deleted before the skill is destroyed, allowing Terraform to remove a skill that still has versions. Defaults to `false`. Set to `true` only if you intend for all versions to be permanently deleted.

~> **Note:** This only deletes versions when the skill is destroyed, not when setting this parameter to `true`. Once this parameter is set to `true`, there must be a successful `terraform apply` run before a destroy is required to update this value in the resource state. Without a successful `terraform apply` after this parameter is set, this flag will have no effect. If setting this field in the same operation that would require replacing the skill or destroying the skill, this flag will not work. Additionally, when importing a skill, a successful `terraform apply` is required to set this value in state before it will take effect on a destroy operation.

### Read-Only

- `created_at` (String) ISO 8601 timestamp of when the skill was created.
- `file_hashes` (Map of String) SHA-256 file content hashes, keyed by path relative to the bundle root. Files must be available during planning and applying.
- `id` (String) Unique skill identifier assigned by the API.
- `latest_version` (String) The latest version identifier for the skill.
- `source` (String) Source of the skill. For user-created skills this is `"custom"`.
- `updated_at` (String) ISO 8601 timestamp of when the skill was last updated.


## Local file tracking

The provider computes `file_hashes` during planning using SHA-256 and paths relative
to the bundle root. Local files must be readable during both plan and apply. Moving
a bundle without changing its relative paths or contents keeps the hashes stable.
If files change after a saved plan, apply fails before uploading; create a fresh plan.

On the first apply after upgrading from a version without `file_hashes`, or after
importing and attaching local files, the provider adopts the local hashes without
uploading solely for adoption. This establishes a baseline; it does not verify that
the existing remote bundle matches local contents. A content edit made before
adoption cannot be detected. Later edits are tracked normally.

Editing file contents or adding/removing files publishes a new version while keeping
the skill ID. A local bundle relocation or `force_destroy` change only updates state.
Changes to `display_title` still replace the skill. The skill resource tracks the
latest version; use a separate skill-version resource when managing a pinned version.

## Import

Import an existing skill using its ID:

```shell
terraform import anthropic_skill.example <skill_id>
```
